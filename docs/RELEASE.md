# Release checklist (plugin update)

Checked against `tools/build_index.py`, `.github/workflows/publish.yml` and the existing tests on `origin/main` `b84569e`. Example below is ai_autoreply; other plugins skip the test-pin step.

1. **Branch** from fresh `origin/main` (`git fetch origin && git switch -c <branch> origin/main`, or a separate worktree).
2. **Bump the plugin file** `plugins/<id>/<id>.plugin`: `__version__` (SemVer, greater than the latest published) and `__version_code__` (integer, strictly greater than every published one; CI also fails on regression). Both lines are adjacent: `__version__ = "x.y.z"` then `__version_code__ = N`. Keep the file at most 2097152 bytes (`stat -c %s plugins/<id>/<id>.plugin`); above 524288 bytes the plugin appears only in `index-v2.json` and `build` raises its `minAppVersion` to at least 0.2.5 (validate prints a warning; app <= 0.2.4 never sees it), UTF-8, LF, no BOM. Adding a permission holds the update until the user approves.
3. **Version pins in tests** (ai_autoreply only; they fail otherwise):
   - `tests/test_ai_autoreply_v034.py`: the assertion that counts `'__version__ = "0.8.1"\n__version_code__ = 40'` (line ~527).
   - `tests/test_ai_autoreply_v036.py`: `assertEqual(mod.__version__, "0.8.1")` and `assertEqual(mod.__version_code__, 40)` (lines ~825-826).
   - Find any others: `grep -rn "__version" tests | grep -v "^tests/.*mod\.__version__ ="` and `grep -rn '"0\.8\.1"' tests`. Earlier size-trim commits also touched `tests/test_ai_autoreply.py` and `tests/test_ai_autoreply_v053.py`, so grep, do not assume.
4. **CHANGELOG** `plugins/<id>/CHANGELOG.md`: add a `## x.y.z` section at the top (the index uses the text under that exact heading, first 500 characters, as the store text). Plain language, in Russian as in existing entries.
5. **Tests for the change** in `tests/` (new file or extend one).
6. **Run all tests**: `python3 -m pytest -q tests` (869 pass at 0.8.1; takes a few seconds).
7. **Release report**: finish the plugin file first, then `sha256sum plugins/<id>/<id>.plugin`. Append an entry to `docs/release-reports.json` (`"schema": 1`, `releases` array): `product`, `version`, `sha256` (of the final file; recompute after any later edit), `checks` (honest test count and what was not verified, for example phone behaviour), and `items` with `id`, `title`, `scope` (complete/partial), `details`, `limitations`, `human_text`. The file is not read by `build_index.py` or CI, so nothing validates it: check by hand that it is valid JSON (`python3 -c "import json;json.load(open('docs/release-reports.json'))"`) and that the sha256 matches.
8. **Delete caches, then validate**: `find . -name __pycache__ -type d -prune -exec rm -rf {} +` then `python3 tools/build_index.py validate`. Stray `__pycache__` inside `plugins/<id>/` is reported as an unexpected sub-directory (`.gitignore` hides it from git but not from the validator running on your disk). Allowed files per plugin dir: `<id>.plugin`, `CHANGELOG.md`, `icon.png`, `meta.json`, `revoked.json`, `README.md`.
9. **Commit** (message ends with the `Claude-Session:` line when made by a Claude session) and `git push -u origin <branch>`.
10. **Pull request** to `main`. CI `publish.yml` job `validate` runs `python tools/build_index.py validate` on Python 3.13 and never publishes. Wait for it to pass.
11. **Merge** (squash was used for #21; earlier PRs used merge commits). The push to `main` triggers the `publish` job: fetches previous index from the `index` branch, `build` (URLs pinned to the commit sha), `sign` with secret `INDEX_SIGNING_KEY`, verify, then force-pushes an orphan `index` branch with `index.json`, `index.json.sig`, `index-v2.json` and `index-v2.json.sig`. `build` writes both files with the same `sequence`: `index.json` has only versions <= 512 KiB (a plugin with only bigger versions is absent), `index-v2.json` has all versions. History comes from the previous `index-v2.json` (fallback: previous `index.json` on the first run, when `index-v2.json` does not exist yet). Both files are signed with the same key. The workflow also runs weekly (Monday 04:17 UTC) to refresh `expires` (generated + 60 days) and can be started manually.
12. **Verify the index**: `gh run list --workflow publish.yml --limit 3` shows success for the merge commit; then
    `git fetch origin index && git show FETCH_HEAD:index.json | python3 -c "import json,sys;d=json.load(sys.stdin);print(d['sequence']);[print(p['id'],p['versions'][0]['version'],p['versions'][0]['versionCode']) for p in d['plugins']]"`. The commit message on `index` reads `index: sequence N from <sha7>` where `<sha7>` is the merge commit. Compare the `sha256`/`size` of the new version in the index with `sha256sum`/`stat` of the file on `main`. Note: use `FETCH_HEAD` or `git fetch origin index:refs/remotes/origin/index` since a plain fetch of other refs may leave `origin/index` stale.
13. **Pull a bad release**: add its `__version_code__` to `plugins/<id>/revoked.json` and publish a higher version; never edit published entries.
14. **Phone check**: no automated device test exists; record in `checks` that behaviour is unverified until someone tests it.
